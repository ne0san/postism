# ローカルで本物の LLM を使う(オーナーのみ)

LLM を使う機能は、まだ実装していない。実装後は、ローカルの既定で、LLM のリポジトリに偽物の実装(固定の応答を返す)を使い、キーは要らない方針。テストや、Claude Code が動かす確認は、すべてこちらで行う。

この手順は、オーナーが手元で本物の LLM(Claude、Jev)を呼んで確かめたいときだけに使う。

> **今の状態:** キーの登録と参照のファイルの作成(下の 1〜3)は、今から準備できる。本物を使った起動(4)は、まだ使えない。アプリ側で本物のリポジトリに切り替える仕組みと、sam local のコンテナへキーを渡す仕組みは、LLM を使う機能の実装と一緒に作る。

## 原則

- 本物を使うのはオーナーだけ。Claude Code の外のターミナルで行う。
- キーの実物を、次のどこにも出さない。
  - Claude Code の会話
  - リポジトリ(コミット、PR、Issue)
  - ファイル(参照のファイルには、キーではなく参照だけを書く)
  - devenv の env、シェルの履歴、ログ
- `op run` の `--no-masking` は使わない(出力に出たキーの値が、伏せ字にならなくなる)。

## 対象のプロバイダーと環境変数

| プロバイダー | 環境変数 | キーを発行する場所 |
| --- | --- | --- |
| Claude(Anthropic) | `ANTHROPIC_API_KEY` | Anthropic の管理画面(Console) |
| Jev(TypeSafe AI) | `TYPESAFE_API_KEY` | TypeSafe AI の管理画面 |

キーはプロバイダーごとに別々に持つ。

## 1. 1Password の CLI を使えるようにする(初回だけ)

- 1Password のアプリの設定で、CLI との連携(Developer の「Integrate with 1Password CLI」)を有効にする。
- `op` を使うたびに、Touch ID などでオーナーの認証が求められる。

`op` は 1Password の CLI。`op --version` で入っていることを確かめられる。

## 2. キーを 1Password に登録する(初回だけ)

1Password のアプリで、プロバイダーごとに項目を作り(種類は「API Credential」など)、キーを入れる。保管庫と項目の名前は自由に決めてよい。

キーの値は、アプリの画面で直接貼り付ける。ターミナルのコマンドの引数に書かない(シェルの履歴に残るため)。

## 3. 参照のファイルを作る(初回だけ)

リポジトリの直下の `.local/llm-keys.env` に、キーの実物ではなく、1Password の参照を書く。`.local/` は gitignore 済みなので、コミットされない。

```
ANTHROPIC_API_KEY=op://<保管庫>/<項目>/credential
TYPESAFE_API_KEY=op://<保管庫>/<項目>/credential
```

参照は、1Password の項目のフィールドのメニューにある「Copy Secret Reference」で得られる。フィールド名が `credential` でなければ、得られた参照をそのまま使う。

## 4. 本物を使って起動する(LLM を使う機能の実装後に使える)

起動するコマンドを `op run` で包む。参照は、そのコマンドの環境変数としてだけ解決され、ファイルには書き出されない。

```sh
op run --env-file=.local/llm-keys.env -- bun run start-api
```

- キーは、包んだコマンドと、そのコマンドが起動するプロセス(sam local のコンテナを含む)の環境変数にだけ入る。
- アプリが本物のリポジトリを使うための切り替え(`LLM_MODE=real` を想定)と、sam local のコンテナへのキーの受け渡しは、まだ無い。実装したら、この節を具体的なコマンドに更新する。

## 5. キーを更新する、無効にする

- キーを替えるときは、1Password の項目を更新するだけでよい。参照のファイルは変えなくてよい。
- キーが漏れた疑いがあるときは、次の順で行う。
  1. 各社の管理画面で、そのキーを無効にする。
  2. 新しいキーを発行し、1Password の項目を更新する。

## Claude Code との関係

- Claude Code のセッションでは、本物の LLM を使わない。キーや、参照を解決した結果を、会話に貼らない。
- Claude Code が `op` を実行しようとすると、1Password からオーナーに認証が求められる。身に覚えがなければ拒否する。
- 1Password の CLI は、一度許可すると、同じターミナルでしばらく許可が続く(期間などの細部は未確認)。`op` を許可したばかりのターミナルでは、Claude Code を動かさない。
- Claude Code の側の制御(拒否の規則や sandbox)は入れない。1Password の認証で十分と判断した(2026-11-20)。
